1. ACTORS
================================================================================

| Actor                  | Role in system                                              |
|------------------------|-------------------------------------------------------------|
| Director               | Full access, manages users, classrooms, reports             |
| Educator               | Manages own classroom, marks attendance, views schedule     |
| Transport Coordinator  | Manages routes, vehicles, child transport assignments       |
| Catering Staff         | Creates menus, meal plans, logs meals                       |
| Parent                 | Views own child's profile, attendance, schedule, transport  |

3. MCD — Modèle Conceptuel de Données
================================================================================

Entities and relationships with cardinalities:

Role ──(1,1)── HAS ──(0,N)── User
User ──(0,1)── ASSIGNED_TO ──(0,N)── Classroom
Child ──(N,1)── BELONGS_TO ──(1,N)── Classroom
Child ──(N,M)── LINKED_TO (via ChildParentLink) ── User[Parent]
Child ──(1,N)── HAS ────────────────────────────── AttendanceLog
User ──(0,N)── MARKS ───────────────────────────── AttendanceLog
User ──(0,N)── GENERATES ───────────────────────── AuditLog

-- Module 3: Schedule
Classroom ──(1,N)── HAS ──────── Schedule
Schedule ──(N,1)── CONTAINS ──── Activity

-- Module 4: Transport
Child ──(N,M)── ASSIGNED_TO (via TransportAssignment) ── Route
Route ──(N,1)── USES ──────────── Vehicle
Child ──(1,N)── HAS ────────────── TransportLog
User[TransportCoord] ──(0,N)── LOGS ── TransportLog

-- Module 5: Catering
Classroom ──(N,M)── FOLLOWS (via MealPlan) ── Menu
Child ──(1,N)── HAS ────────────── MealLog
MealLog ──(N,1)── REFERENCES ───── Menu

5. UML — Use Case Diagram (by actor)
================================================================================

DIRECTOR
  - Manage users (create, activate, deactivate)
  - Assign educators to classrooms
  - View all classrooms and children
  - View attendance reports (all classrooms)
  - View audit logs
  - Manage catering menus and meal plans
  - View transport routes

EDUCATOR
  - View own classroom children
  - Mark / update daily attendance
  - View weekly schedule for own classroom
  - Enrol new child

TRANSPORT COORDINATOR
  - Manage vehicles and routes
  - Assign children to routes
  - Log daily transport status (picked up / dropped off / absent)

CATERING STAFF
  - Create and edit menus
  - Assign meal plans to classrooms
  - Log daily meal consumption per child

PARENT
  - View own child's profile
  - View own child's attendance history
  - View own child's schedule
  - View own child's transport assignment
  - View own child's meal plan

6. UML — Key Sequence Diagrams
================================================================================

1. LOGIN
   Client → POST /api/auth/login
          → validate input
          → query users JOIN roles WHERE email = ?
          → bcrypt.compare(password, hash)
          → jwt.sign({ userId, roleId, roleName })
          → return { token, user }

2. MARK ATTENDANCE
   Educator → POST /api/attendance/mark
            → authenticate (JWT)
            → checkRole(Director | Educator)
            → if Educator: verify child is in own classroom
            → INSERT ... ON DUPLICATE KEY UPDATE attendance_logs
            → logAction(audit)
            → return { success }

3. ENROL CHILD
   Director → POST /api/children
            → authenticate (JWT)
            → checkRole(Director | Educator)
            → validate input
            → INSERT INTO children
            → return { child_id, profile }

4. ASSIGN EDUCATOR TO CLASSROOM
   Director → PATCH /api/classrooms/:id
            → authenticate (JWT)
            → checkRole(Director)
            → UPDATE classrooms SET educator_id = ?
            → return { updated classroom }

5. VIEW CHILD ATTENDANCE HISTORY (Parent)
   Parent → GET /api/attendance/child/:id
          → authenticate (JWT)
          → checkRole(Director | Educator | Parent)
          → if Parent: SELECT 1 FROM child_parent_link WHERE child_id = ? AND parent_user_id = ?
          → SELECT attendance_logs WHERE child_id = ? last 60 days
          → return { child, stats, logs }
